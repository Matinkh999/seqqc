# seqqc

یک ابزار کوچک و قابل‌توسعه‌ی پایتونی برای کنترل کیفیت داده‌های توالی‌یابی DNA (فرمت‌های FASTQ / FASTA).

> وضعیت: هفته ۲ از ۸ — خواننده‌ی FASTQ با اعتبارسنجی، میانگین Phred هر خوانش، Q20/Q30 و پردازش جریانی (streaming).

## قابلیت‌های برنامه‌ریزی‌شده

- خواننده‌ی جریانی (streaming) FASTQ/FASTA با پشتیبانی از gzip؛ مصرف حافظه با بزرگ‌شدن فایل بیشتر نمی‌شود
- شاخص‌ها: محتوای GC، میانگین کیفیت Phred (در هر موقعیت و در هر خوانش)، توزیع نوکلئوتیدها، Q20/Q30
- گزارش HTML مستقل (نمودارها داخل فایل تعبیه می‌شوند) و یک فایل JSON با همه‌ی مقادیر
- سازوکار افزونه (plugin): افزودن شاخص جدید به‌صورت یک فایل کوچک پایتون، بدون تغییر هسته
- اعتبارسنجی با FastQC روی مجموعه‌داده‌های عمومی

## راه‌اندازی برای توسعه

```bash
python -m venv .venv
source .venv/bin/activate          # ویندوز (CMD): .venv\Scripts\activate
```

## خلاصه‌ی کیفیت یک فایل FASTQ

```bash
python scripts/fastq_qc.py tests/data/sample_dna_reads.fastq
```

```

bases               : 500
read length         : mean 50.0 (min 50, max 50)
mean Phred (bases)  : 35.70
mean Phred per read : min 20.00 / mean 35.70 / max 40.00
Q20 (Q >= 20)       : 100.00 %
Q30 (Q >= 30)       : 80.00 %

first 5 reads
read_id           length  mean_Phred
READ_001              50       40.00
READ_002              50       39.00
READ_003              50       20.00
READ_004              50       40.00
READ_005              50       40.00
```

- میانگین Phred هر خوانش برابر میانگین حسابی امتیاز Phred بازهای آن خوانش است (Q = کد ASCII منهای ۳۳).
- Q20 و Q30 درصد کل فایل‌اند: سهم همه‌ی بازهای فایل که Q آن‌ها دست‌کم ۲۰ و دست‌کم ۳۰ است (بازی که دقیقاً Q = 20 دارد هم Q20 حساب می‌شود).
- گزینه‌ها: `--per-read means.csv` میانگین Phred هر خوانش را در یک فایل CSV می‌نویسد، `--show N` میانگین N خوانش اول را چاپ می‌کند (پیش‌فرض ۵) و `--offset 64` برای داده‌های قدیمی Illumina است. فایل‌های فشرده‌ی gzip (پسوند gz) هم کار می‌کنند.

### چه چیزی اعتبارسنجی می‌شود

`read_fastq` هر رکورد را بررسی می‌کند و با پیامی که شماره‌ی رکورد و خط را می‌گوید متوقف می‌شود:

1. خط شناسه با `@` شروع شود
2. خط سوم با `+` شروع شود
3. طول توالی و رشته‌ی کیفیت برابر باشد
4. توالی فقط شامل A، C، G، T و N باشد
5. هر نویسه‌ی کیفیت در بازه‌ی مجاز offset انتخابی باشد
6. فایل وسط یک رکورد تمام نشود

### پردازش جریانی (Streaming)

فایل خط‌به‌خط خوانده می‌شود و فقط چند شمارنده در حافظه می‌ماند؛ پس مصرف حافظه به اندازه‌ی فایل بستگی ندارد. روی فایل‌های ساخته‌شده (لینوکس، Python 3.12) بیشینه‌ی حافظه هم برای ۱۰۰٬۰۰۰ خوانش (فایل ۲۱ مگابایتی) و هم برای ۱٬۰۰۰٬۰۰۰ خوانش (فایل ۲۱۶ مگابایتی) حدود ۱۴ مگابایت بود. نسخه‌ای که همه‌ی خوانش‌ها را در یک لیست نگه می‌دارد برای ۱۰۰٬۰۰۰ خوانش ۵۶ مگابایت و برای ۴۰۰٬۰۰۰ خوانش ۱۸۷ مگابایت لازم داشت. فایل `tests/test_streaming.py` این را خودکار بررسی می‌کند.

## طول و درصد GC یک فایل FASTA

```bash
python scripts/fasta_gc.py tests/data/tiny.fasta
```

```
sequence                length      GC%
seq1                        20    35.00
seq2                         8     0.00
TOTAL                       28    25.00
```

درصد GC برابر است با (G + C) / (A + C + G + T) × 100. حرف N و سایر نمادهای مبهم در طول توالی حساب می‌شوند ولی در مخرج GC% نه. فایل‌های فشرده‌ی gzip (پسوند gz) هم کار می‌کنند. توالی‌ها خط‌به‌خط شمرده می‌شوند و هیچ‌وقت ذخیره نمی‌شوند؛ پس اینجا هم پردازش جریانی است.

## ساختار پروژه

- `src/seqqc/`: بسته‌ی اصلی (io، fastq_stats، fasta_stats، metrics، report، plugins، cli)
- `tests/`: آزمون‌های واحد؛ پوشه‌ی `tests/data` فایل‌های نمونه را نگه می‌دارد
- `docs/formulas.md`: تعریف هر شاخص (به فارسی)
- `scripts/`: `fastq_qc.py` و `fasta_gc.py` (بعداً: مقایسه با FastQC)

## نقشه‌ی راه

1. طراحی، فرمول‌ها، مخزن (انجام شد)
2. خواننده‌ی FASTQ با اعتبارسنجی، میانگین Phred هر خوانش، Q20/Q30 و پردازش جریانی (انجام شد)
3. شاخص‌های Phred در هر موقعیت (میانگین، میانه، چارک‌ها) و توزیع نوکلئوتیدها
4. شاخص‌های GC برای FASTQ، رابط خط فرمان (گزارش طول و GC% برای FASTA از قبل انجام شده است)
5. نمودارها و گزارش HTML/JSON
6. سازوکار افزونه و دو افزونه‌ی نمونه
7. مقایسه با FastQC روی سه مجموعه‌داده‌ی عمومی
8. مستندسازی، گزارش نهایی و زمان ذخیره
